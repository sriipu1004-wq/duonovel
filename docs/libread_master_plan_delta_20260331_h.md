更新日: 2026-03-31
用途: 子チャットでの同期指示と、同期完了後の引き継ぎ文更新ルールの追補
扱い: このファイルの内容は、以後の親チャット判断と子チャット引き継ぎで `docs/libread_master_plan.md` と同等に扱う

---

## 1. 動作確認後に同期だけが残った時の扱い

- 子チャット作業で、**動作確認が完了し、残りが同期だけになった場合** は、その時点で親チャットまたは子チャット文面内に **同期の指示** を出す
- この同期指示は、少なくとも次を含む形を基本とする
  - 現在ブランチ確認
  - `git status`
  - `git rev-parse HEAD`
  - `git rev-parse origin/main`
  - 必要なら `git fetch origin`
  - 必要なら `git pull --ff-only origin main`
  - 必要なら commit / push
- 子チャットは、動作確認済みなのに同期手順が抜けたまま終わらない

---

## 2. 同期完了後の引き継ぎ文

- 同期が完了したら、その内容を **引き継ぎ文 / 親チャット向け報告文に加える**
- その上で、**同期情報込みの全文** を改めて出す
- 同期情報として最低限含めるもの
  - 現在ブランチ
  - `git status`
  - local HEAD
  - origin/main HEAD
  - 同期状況
  - GitHub に push 済みの commit hash

---

## 3. 子チャット引き継ぎ文への反映

- 以後、子チャットへ渡す引き継ぎ文には、この同期ルールを前提として含める
- 特に、子チャットでほしい報告内容には
  - 動作確認後に同期だけが残った場合は同期指示を出すこと
  - 同期完了後は同期内容込みの全文を出すこと
  を含める

---

## 4. 扱い

- この追補は親チャット正史として扱う
- 以後の子チャット運用と引き継ぎ文作成では、このルールを反映する
- 後で `docs/libread_master_plan.md` を直接更新できるタイミングが来たら、その内容へ統合する
