## Why H2 exists

Previously a service-role-created \`createSignedUploadUrl(..., {upsert:true})\` granted a bearer upload capability that was independently valid for **2 hours**. A DB consent revocation or owner emergency PRIVATE+R18 correction did **not** revoke that token. The previous multipart finalize handler also called Storage \`remove(paths)\` unconditionally in \`finally\`, even if a token could still write later. Neither app permission checks nor deleting the current object is sufficient to revoke a still-valid bearer upload.

The public Human narration workflow is separate from PRIVATE temporary stage bytes. The server must **not** treat signed upload availability as Human recording publication consent, physical byte custody, the right to overwrite prior media, or permission to remove other users' files.

## Bounded source changes

1. \`scripts/issue137-b2/r0-h2-signed-staging-lease-extension.sql\`: **nondeployable reviewer candidate**. New \`libread_internal.h2_human_stage_lease\` per-session register with actor/series/episode, canonical source extension/size/part count, ACTIVE/SEALED/ABORTED/RETIRING/RETIRED state, **90-minute write eligibility** and **3-hour no-delete window** measured from issuance. Only service_role can invoke H2 exposed open, close, retirement-candidate, claim and receipt RPCs. \`anon\` / \`authenticated\` have no EXECUTE or private-table permissions. There is deliberately NO Scheduler/Cron and no access-key management.
2. \`issue137_h2_stage_storage_guard\` on \`storage.objects\` INSERT/UPDATE of the **new** \`human-recording-audio/human-temp/<series>/<episode>/<actor>/<session>/part-NNNN.ext\` namespace. The trigger enforces a registered ACTIVE, unexpired, immutable path/part number and revalidates source GENERAL/public, episode posted/public, recording open and global consent \`2026-04-16\` against Postgres, with row locks. This is intended to stop a *previously signed* bearer after the source or consent is revoked, even if a Storage request bypasses RLS. It is not a cryptographic revocation of the token. For any in-flight operation the chosen transaction serialization point, not wall-clock response completion, decides whether the write preceded revocation.
3. \`human-upload-session\` checks signed-in human actor, current public GENERAL source/episode and consent before minting any token. A new UUID lease is committed using a server-only H2 RPC **first**, then token issuance uses **\`upsert:false\`**. On a partially failed issue response, close the lease; never remove private bytes based on unknown in-flight token state.
4. \`human-upload-finalize\` seals the exact owner/session/scope by server-only RPC **before** part download. A missing, stale, expired, already-closed or unauthorized lease fails closed. Independent Human publication/ownership/consent/H1 revision checks still apply during \`publishHumanRecording\`. Failure/success no longer immediately removes temporary parts. \`human-upload-abort\` allows the signed-in actor to close their own ACTIVE lease without deleting bytes. Aborting or sealing does not itself assert the media was physically deleted. New bearer tokens cannot write the closed lease via Storage guard.
5. **Conservative retention:** original temp parts remain PRIVATE after SEAL/ABORT for a minimum 3-hour grace after lease registration, longer than the documented signed-upload token lifetime (2h); the H2 guard disables writes after the earlier 90-minute eligibility threshold. \`issue137_h2_stage_retire_candidates\` only lists matured leases. A separate, explicitly authorized janitor must first **claim** the exact session (blocks writes), independently reconcile its Storage prefix to expected part count/names and DB recording references, delete only exact reviewed paths through Storage API, re-read the physical origin, then call **finish**; the DB receipt refuses to mark RETIRED while objects/references remain. A partial delete leaves RETIRING for safe reconciliation, never a false successful status.
6. The **only automatic cleanup in this PR is disposable synthetic fixture deletion when GitHub CI tears down its owned local Docker stack**. \`r0-h2-local-advance-expiry-only.sql\` artificially ages only known synthetic ABORTED leases after checking the unlinked local sentinel. \`r0-h2-local-retirement-e2e.mjs\` exercises the claim/inventory/physical Storage remove/receipt protocol against those bytes. The time fast-forward is **not** an actual three-hour real-time test or Production retention worker.

## Explicit safe-stop conditions

- H2 SQL missing, RPC denied, actor/episode/series/part mismatch, withdrawn or R18 source, missing/current-invalid consent, expired or closed lease, another user abort, file overwrite attempt: **reject and do not fall back to direct service-role writes**.
- Unexpected file, sidecar, unlisted part, nested folder, DB reference, listing error, or incomplete Storage API response: **MANIFEST/RIGHTS HOLD**. Never expand deletion scope automatically, delete a published original, or use a wildcard.
- Do not immediately delete on finalize failure, tab close or network timeout: the server cannot infer an in-flight Storage request's outcome from a Next.js timeout.
- Do not silently start a hosted Cron or retention worker. Any real DB/Storage delete requires a separate decision specifying project, bucket, prefix/object count, source rights, custody, affected actors and rollback.
- A new H2 feature migration does not secure **previously issued legacy \`human/\` or untracked multipart/TUS signed upload tokens**. Transition inventory + token lifetime quarantine must be separately reviewed; do not assume a newly installed trigger revokes old bearer URLs outside \`human-temp/\`.
- The source, consent, and lease locking boundaries require an independent security concurrency audit. Runtime key/cookie isolation, static S3 credentials, privileged direct backend Storage APIs, R18/CDN/public-origin recall, actual non-synthetic large audio, cross-region availability, crash-recovery of DB+bytes, rights to the six historic Human-prefixed public objects and #150 performance are **NOT PROVEN** by the local tests.
