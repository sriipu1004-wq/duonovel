## 追加した優先タスク
### 1. アカウント作成規約・同意導線MVP
- 目的
  - アカウント作成時に、最低限必要な規約・同意を取る
- 最低限含めるもの
  - 利用規約への同意
  - プライバシーポリシーへの同意
  - 年齢・行為制限に関する最低限の確認
  - 表示名、プロフィール、投稿コンテンツが公開されうることの明示
  - 違反時の利用停止、削除、制限の可能性の明示
- 実装観点
  - 新規登録フォームの送信前チェック
  - Google / Apple / メール登録のどの導線でも同じ同意状態を取れるようにする
  - 初回登録後にしか出せない情報と、登録前に見せるべき情報を切り分ける

### 2. 新規作成導線強化MVP
- 目的
  - アカウント新規作成を「人が入りやすい形」へ整える
- 含める内容
  - Google ログイン / 登録導線
  - Apple ログイン / 登録導線
  - 既存メール登録との並び整理
  - 初回プロフィール設定導線
  - 本人確認方法の方針整理
  - 不正作成 / なりすまし / 量産対策の最小設計

### 3. サーバー運用・スケーリング方針MVP
- 目的
  - 大人数を LIB read に入れる前提で、落ちにくい最小運用方針を固める
- 含める内容
  - どこがボトルネックになりやすいかの棚卸し
    - 読むページ
    - 音声配信
    - 画像 / BGM / 音声ストレージ
    - DB 読み書き
    - 認証
  - 初期公開時の想定負荷の整理
  - キャッシュや配信の考え方
  - Supabase / hosting / storage / audio 配信まわりの役割整理
  - 監視、障害時の最低限対応方針

### 4. 軽量化・快適化MVP
- 目的
  - 初期公開で、ユーザーが「重い」「読みにくい」「再生がもたつく」と感じにくい状態へ寄せる
- 含める内容
  - ホーム / 検索 / 作品ページ / 読むページの初期表示負荷の見直し
  - 不要な取得や過剰な再レンダリングの削減
  - 画像 / 音声 / BGM の読み込みタイミング整理
  - 再生ビューでの不要な state 更新や描画負荷の整理
  - ストレージ配信、キャッシュ、プリロード方針の最小整理
  - モバイル回線や低スペック端末でも破綻しにくい表示・再生方針
- ここでは「理想的な最適化」ではなく、公開前に効く軽量化を優先する

## 子チャット運用メモ
- 分野の被る子チャットがあれば、それを優先して使う
- なるべく新規子チャットを作らない
- 子20, 子21, 子22 は使わない
- 次差分は公開制御系なので、子23以降を使う
- アカウント作成規約・同意導線は signup / auth / legal の子チャットで扱うのが自然
- 新規作成導線強化は auth / signup 系の子チャットで扱うのが自然
- サーバー運用・スケーリング方針は infra / 性能整理系の子チャットで扱うのが自然
- 軽量化・快適化MVPは performance / rendering / fetch 最適化系の子チャットで扱うのが自然
- 実ファイルの実際のコード位置・実インデント・前後文脈を確認してから、そのまま貼り付けられる完成コードを出す
- 説明用に左へ寄せたコードは出さない

## コード差し込みルール
- 実ファイルの該当箇所を確認してから、その位置にそのまま貼れる字下げで出す
- 差し込み位置が危険なら丸ごと置換用コードを優先する
- sibling の列・インデントが崩れるコードは不合格
