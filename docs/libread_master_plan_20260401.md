## 2. 現在の固定方針

### 2-1. 作者向け導線
- 作者向け主導線は **作品ワークスペース中心**
- 現在の整理:
  - `/write` = 作品ワークスペース一覧
  - `/write/series/[seriesId]` = 作品ワークスペース本体
  - `/manage` = backward 互換 redirect
  - `/manage/series/[seriesId]` = backward 互換 redirect
- 管理トップは軽い入口として扱い、作品ごとの実作業は作品ワークスペースへ寄せる
- 作品に表示される導線のうち **管理ハブ** は削除する
- 以後は、作品ごとの実作業導線を **作品ワークスペース中心** に統一する

### 2-2. 本文編集ページ
- `WriteEpisodeForm.tsx` は **本文編集中心**
- 本文編集ページに設定を詰め込みすぎない
- 作品全体の方向付けは作品ワークスペース側で持つ
- 本文だけスクロールしやすい構造を維持する

### 2-3. 朗読導線
- 朗読の主導線は **`/record`**
- 作品ページでは朗読可否表示は残すが、申請や制作開始の主動線は `/record` に集約
- 朗読許可状態:
  - `open`
  - `closed`
  - `approval_required`
- 管理ハブ的な新導線は増やさない

### 2-4. BGM / 演出方針
- 外部持ち込みBGM前提では進めない
- サイト用意BGM中心
- `bgm_library` を素材正史とする
- 既存 read 側互換のため、当面は `bgm_title / bgm_audio_path / bgm_settings` を併用
- BGM素材ページは **ユーザー向け公開素材ライブラリ + 自分専用の素材投入・管理基盤** として育てる
- BGM素材追加は **運営側のみ**、一般ユーザーは不可
- BGM の「お気に入り」は **BGM素材用 favorite** として扱い、作品保存機能とは混同しない
- 今後 BGM は大きく増える前提で設計する
- そのため、**BGM編集画面ではお気に入りしたものだけを表示する方向を基本** とする
- その旨を UI 上で明記する

#### 責務分離の固定ルール
- 演出は **既定演出設定** と **演出編集** に責務分離して扱う
- **既定演出設定** は、作品共通の既定値を置く場所
  - 共通BGM
  - 既定フォント
  - 既定文字色
  - 既定背景
  - 作品共通のプレビュー確認
- **各話演出編集** は、その話限定の設定を置く場所
  - 各話BGM
  - その話限定の背景
  - 文字演出
  - 挿絵
  - 場面転換
  - その他その話固有の演出
- 今後の機能追加でも、この割当を崩さない
- 作品共通の既定値を episode 側へ戻さない
- 各話固有設定を既定演出設定側へ混ぜない
- 既定演出設定ページの責務と、演出編集ページの責務を曖昧にしない

#### 詳細機能追加時の確認ルール
- 詳細な機能を足す時は、**repo の実ファイルを先に確認する**
- 確認対象には少なくとも次を含める
  - route
  - 型
  - helper
  - 保存先カラム / settings 構造
  - 既存コンポーネント名
- 仕様だけで判断せず、**repo 上の既存の名前と責務に結びつけて** 実装判断する
- 名前が近いから同じ責務だと決めつけず、実ファイル上の入出力と保存先を確認する
- 詳細機能を入れる時ほど、この確認を省略しない

### 2-5. 作者ページ / マイページ
- 公開面 = `/authors/[authorId]`
- 本人面 = `/mypage`
- 完全統合ではなく、土台共通化 + 公開面 / 本人面 分離
- `/mypage` は活動ハブ
- 新規作品作成の主導線は `/write`

### 2-6. 反応機能の正式整理
- **ブックマーク** = 作品保存
- **いいね** = 軽い反応 / 人気度の簡易指標
- **レビュー** = 作品単位の言葉の反応
- **エピソードコメント** = 各話末尾の感想・反応
- それぞれ別機能として育てる
- 旧名称の「応援」は **いいね** に置き換える
- 旧名称の「お気に入り」は、作品保存機能としては **ブックマーク** に置き換える
- ランキングやおすすめ作品を表示する時は、**いいね数** を表示対象に含める
- レビュー欄は、開閉 / レビューいいね / 投稿順・いいね順 / 昇順・降順 / 作者による表示制御 までを最小版として持つ
- エピソードコメント欄は、各話末尾フォーム / コメントいいね / 投稿順・いいね順 / 昇順・降順 / 作者による表示制御 までを最小版として持つ
- 反応機能の最小版は、名称整理・レビュー拡張・エピソードコメント導線・表示制御まで一段完了
- 今後の反応機能追加候補は、spoiler、通報、通知、コメント編集 / 削除、より細かい運用制御

## 4. 演出仕様の固定要望

- 演出は以下の地点から入れるようにしたい
  - 新規小説作成時
  - 次話投稿時
  - 作品ワークスペース
- 設定だけでなく **演出付き本文のプレビュー** が必要
- 今後増える前提で考える
- 既定演出設定と演出編集の責務分離を崩さない

### 想定演出
- BGM
- 場面転換にてBGM変更
- ルビ
- 文字振動
- 文字動作（キーボード打ち込み、フェードアウト等）
- 文字フォント変更
- 文字色変え
- 太字
- 文字斜線
- 文字点強調
- 文字線強調
- 背景変更（紙調、ガラス調、プラスチック調、石調、木材調）
- 挿絵

### 演出編集ページの仕様
- ページ上部あたりに、そのエピソード本文を表示する
- 文字指定演出では
  - 左クリック / 長押しで青線を引いて対象文字を指定
  - リアルタイムで対象文字列として扱う
- 配置が必要なもの
  - 場面転換
  - 背景
  - 挿絵
  などは、**指定行数** により場所を指定
- 行数表示が必要
- 表示予定本文とプレビューは同じ位置に置く
  - デフォルトは本文
  - ボタン1つでプレビューに切替
  - プレビューは仮保存も表示
- このページは **詳細演出の置き場** として扱う

### 背景 / フォント / 色の責務
- 既定背景は **既定演出設定**
- その話だけの背景指定は **各話演出編集**
- 既定フォント / 既定文字色は **既定演出設定**
- 個別の文字演出としての変更は **演出編集**

### BGM場面転換仕様
- 共通BGMは **既定演出設定**
- 各話BGMと場面転換は **各話演出編集**
- エピソード単体BGMと統合して扱う
- 1話通しで同一BGMなら、そのBGMだけ指定
- 転換がある場合は
  - 転換位置
  - 転換後BGM
  - 転換時の切り方
  - 転換時の入り方
  を指定

## 6. 親チャット / 子チャット運用ルール

### 6-1. 子チャット作業の前提
- 子チャットの役割は **VS Code の local ファイル変更指示を出すこと**
- 実際に動かすのはユーザー側とする
- 子チャットは「こちらが動かす前提」で話を進めない
- 以後の実装指示は、原則として **local に存在するファイルをどう直すか** を中心に出す

### 6-2. repo 確認と VS Code local のズレ
- 親チャットが repo 確認を行った時、**repo と VS Code local のズレが見つかったら再判定** を出す
- repo 側で進んでいても、local が追いついていなければ、そのまま次作業へは進めない
- 逆に local だけ進んでいて repo に無い場合も、正式受理や次段階移行は保留する

### 6-3. 詳細機能追加時の確認手順
- 詳細機能を入れる時は、仕様だけで広げず、**repo の実ファイル確認を先に行う**
- 既存 route、型、helper、保存先、既存コンポーネント名を見て、**名前と責務でつなげる**
- 近い名前の画面や helper がある場合は、必ず実体を確認してから再利用 / 拡張を判断する
- 責務分離済みの領域は、既存の割当を崩さない形で追加する

### 6-4. 子チャットへの今後の指示の出し方
- 既存子チャットで十分なら、その子チャット継続を優先する
- 新規子チャットが必要な場合は、単発名ではなく **ある程度汎用性のある担当名** を付ける
- 他チャットへ貼る必要がある長文は、以後 **そのままコピーできるプレーンなコードブロック形式** で出す
