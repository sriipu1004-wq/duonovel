## 2. 音声エンジン方針

### 2-1. 第一候補
**VOICEPEAK 商用可能 6ナレーターセット**
- 商用・業務利用可能な製品として扱う
- 外部で生成した音声を storage + `recordings` に登録して、既存の `read` / `works` / 朗読者棚導線へ乗せる方針を採る
- まずは試作段階で、1話分のサンプル音声を成立させる

### 2-2. 保留候補
**Google Cloud Text-to-Speech**
- 技術的には接続可能
- ただし課金有効化、文字数課金、chunk 分割前提のため、現段階では優先しない
- 後順位で保留

### 2-3. 現段階の実装方針
- まず API 自動生成よりも、**外部生成音声を既存 `recordings` 導線へ安全に乗せる最小導線** を優先する
- つまり
  - VOICEPEAK で音声を外部生成
  - storage へ保存
  - `recordings` 登録
  - `read` / `works` / 朗読者棚で再生
  という最短ルートを優先する

## 8. コード差し込みの厳格ルール
- 必ず repo 実体を確認して、前後の形に厳密に合わせる
- 差し込み位置が曖昧なら、部分差し込みではなく丸ごと置換用の完成コードを優先する
- 貼り付けた時に sibling 要素の列・インデントが1つでも崩れるコードは不合格扱いにする
- JSX の兄弟要素は同じ深さなら同じ字下げで揃える
- 部分差し込みで列ズレの危険がある時は、必ず親の開始タグから閉じタグまで含めた完成ブロックを出す
- 見た目上「たまたま動くかも」で済ませず、貼る前から整形済みの完成コードを出す
