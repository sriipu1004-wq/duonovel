## 公開の SQL

  - `restrictions.sql`：制限の行だけを書く（公開しない）。
  - `apply.sql`：1つの transaction の中で、制限の行を書いて（または restrictions.sql の行と一致するか確かめて）から公開する。制限の行が無い・違う作品があれば全体を止める。公開した後にも「制限の無い公開作品」が無いことを確かめる。snapshot を `libread_internal.pd_region_issue139_cl_20261115_*` に残す。
  - `rollback.sql`：下書きに戻してから、apply.sql が入れた制限の行だけを消す。
- 作品は manifest の id（`effect_settings.publicDomain.manifestId`）で引くので、取り込みの後に作り直す必要は無い（話数・題・注意が変わったら作り直す）。
- **60秒の cache**：アプリは制限を60秒の間 cache する。apply.sql だけで行を書いて公開すると、最大60秒、制限の無い状態で作品ページが出うる。避けるには restrictions.sql を先に流し、2分以上待ってから `--min-restriction-age-seconds=120` で作った apply.sql を流す。どちらにするかは親の判断。
