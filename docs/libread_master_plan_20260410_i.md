## 一般ユーザー朗読導線の固定仕様
- 入口は 2 段構成
  - `/record` = 作品検索・申請・制作開始ポータル
  - `/record/create/[seriesId]` = 実制作ページ
- MVP の入力手段は 2系統
  - ブラウザ録音
  - 既存音声ファイルアップロード
- PC はブラウザ録音主導、スマホはブラウザ録音可能なら利用、難しい端末ではファイルアップロード主導
- 受け入れ形式は `mp3 / m4a / wav / webm / ogg / aac / flac`
- 保存方針は 2層
  - 原本保持
  - 再生用正規化
- recordings は publish 時のみ接続
  - `series_id`
  - `episode_id`
  - `reader_id = user.id`
  - `reader_name = 表示名スナップショット`
  - `audio_storage_path = 再生用正規化音源`
  - `is_public = true`
- 下書きは server 永続なし、client 一時状態のみ
- 差し替えは same episode / same reader の上書き
- `1 episode × 1 reader = 1 public recording` を MVP の単位に固定
- BGM混在音源、複数バージョン保持、ブラウザ編集、server 永続下書きは今回非対応

## 子チャット運用メモ
- 分野の被る子チャットがあれば、それを優先して使う
- なるべく新規子チャットを作らない
- 次差分は同じ録音 / 朗読導線系なので、近い子チャットを優先して使う
- 実ファイルの実際のコード位置・実インデント・前後文脈を確認してから、そのまま貼り付けられる完成コードを出す
- 説明用に左へ寄せたコードは出さない

## コード差し込みルール
- 実ファイルの該当箇所を確認してから、その位置にそのまま貼れる字下げで出す
- 差し込み位置が危険なら丸ごと置換用コードを優先する
- sibling の列・インデントが崩れるコードは不合格
