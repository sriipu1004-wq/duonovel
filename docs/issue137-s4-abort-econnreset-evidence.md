## 2. Actual code ownership and distinct timeout boundaries

- `src/lib/supabase/serverPublic.ts`: `publicReadFetch` wraps the **actual HTTP request**, sets `AbortSignal` 2500ms local deadline and inherits upstream cancellation, logs only allowlisted endpoint and numeric timings on **its own** deadline. This is NOT equivalent to Next.js `unstable_cache` or user request timeout. A warning denotes local timer expiration, not the result of a page request.
- `src/lib/publicWorks.ts` **main**: catalog `public-base-work-cards-v12-canonical-source-language` and recording aggregates `public-recording-aggregates-human-filtered-paged-v2` both use 60s `unstable_cache`. Draft PR #153 has separate later experimental v13 source, not Production.
- `src/lib/reliability/readOnly.ts`: higher-level `runReadOnlyWithRetry` / `ReadOnlyTimeoutError` uses an independent deadline. It does not own the `[public-db-local-timeout]` log. It explicitly avoids retrying its own deadline; the supplied AbortSignal only cancels the underlying work if the caller passes it through.
- `scripts/issue137-b2/human-multipart-stream-next-local-e2e.mjs`: local Next multipart POST uses Node fetch with an Undici keep-alive dispatcher. It has a narrow, tested conflict/ACK-loss path that reads **both** durable SQL intent and physical private bytes before at most one guarded 409. A different POST path still failed with a real ECONNRESET in the first attempt. Blind automatic retry after unknown POST commit can double-write; do not generalize the replay helper or remove the test to manufacture green CI.
- `src/lib/recording/privateMediaProxy.ts`: separate streaming timeout (15 seconds) and byte-range behavior from public Supabase 2500ms. Reader playback and Human uploads are not identical work; do not assume one socket error implies the other.

## 3. Authorized nonproduction experiment

`scripts/issue137-b2/public-abort-vs-transport-local.test.mjs` imports the real `publicReadFetch` source. Uses only a disposable in-process HTTP server bound to **127.0.0.1**, and an explicit no-network fetch substitution for deterministic delayed timer dispatch. Checks:

1. normal local GET → HTTP 200 without a local timeout warning;
2. forcibly destroyed local TCP connection before headers → fetch failed with **no local deadline warning**;
3. already-aborted upstream signal → separate rejection, **no misclassified local deadline**;
4. deliberate 2750ms blocking of a synthetic event loop where the actual 2500ms source timer is scheduled → one `[public-db-local-timeout]` report with `deadlineTimerDelayMs` greater than zero and relatively short `abortSettlementDelayMs`; avoids any external request or keys;
5. endpoint-only allowlisting and no URL/id/query information in timing diagnostic.

This proves **these two failure classes can be distinguished in a controlled local case**. It does **not** prove why Production timers were delayed, or create a general fix. The test must be wired into the existing B2 SOURCE/runtime CI, with exact HEAD raw logs checked. Neither a test PASS nor Preview READY changes the Production outcome.
