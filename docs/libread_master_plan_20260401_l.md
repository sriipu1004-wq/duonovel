## 1. 正式名称
- サービス正式名称は **LIB read（ライブリード）**
- 旧暫定名「デュオノベル」は過去差分や旧文面に残っている場合があるが、新規作業では **LIB read** を正式名称として扱う

---

## 2. 公開モデルの固定仕様
- 作品規模では **公開 / 非公開** を扱う
- エピソード規模では **投稿 / 予約投稿 / 下書き保存** を扱う
- **エピソード規模での公開 / 非公開という考え方は廃止** する
- series 側 canonical は `publication_status`
- episodes 側 canonical は `posting_status`, `scheduled_for`, `posted_at`, `last_edited_at`
- 既存の `is_published / published` は移行期互換として扱う
- 前話が下書きの時は次話を 投稿 / 予約投稿 にできない制約を持たせる
- 前話が予約投稿の時は次話の予約時刻を前話より前にできない制約を持たせる
- 投稿済みエピソードの編集は許可する
- 作品ページでは各話に投稿日を出し、編集済みなら投稿日の隣に編集日と編集済み表示を出す

---

## 3. 再生体験と閲覧演出の固定仕様
- 線が文字を追従する機能を維持・修正する
- 閲覧位置が自動でスクロールする機能を維持・修正する
- 次話自動再生ボタンを配置し、ON/OFF を切り替えられるようにする
- 手動の前話 / 次話遷移では autoplay しない
- 演出設定は少なくともプレビューどおりに作品閲覧ページへ反映されることを目標にする
- scene cue の最小 runtime 発火は完了済み
- 作品閲覧ページの朗読フッターは中央揃えで、左から `栞 / 倍速 / 前話 / 再生 / 次話 / 自動追尾 / 設定` の順で置く
- **自動追尾中は反応無し** とする
- 設定画面表示中は本文を非表示にしてよい
- 設定画面を閉じた時は元のスクロール位置へ戻る
- 表示演出欄は現段階では `全演出を非表示 / 文字サイズ / 行間` に限定する
- 朗読欄には少なくとも `朗読音量 / 次話自動再生 / 朗読停止` を置く

## 4. 作者向け / 演出の固定方針
- 作者向け主導線は **作品ワークスペース中心**
- `/write` = 作品ワークスペース一覧
- `/write/series/[seriesId]` = 作品ワークスペース本体
- `/manage` と `/manage/series/[seriesId]` は backward 互換 redirect
- `WriteEpisodeForm.tsx` は **本文編集中心**
- 演出は **既定演出設定** と **演出編集** に責務分離して扱う
- **既定演出設定** は作品共通の既定値を置く場所
  - 共通BGM
  - 既定フォント
  - 既定文字色
  - 既定背景
  - 作品共通のプレビュー確認
- **各話演出編集** はその話限定の設定を置く場所
  - 各話BGM
  - その話限定の背景
  - 文字演出
  - 挿絵
  - 場面転換
  - その他その話固有の演出
- 今後の機能追加でも、この割当を崩さない

## 5. 「見せる前提」優先順位ラベル

### 5-1. ラベル定義
- **SHOW-CORE**
  - 人に見せた瞬間の印象を決める中核
  - 試作の見える化に直結
- **SHOW-DEMO**
  - 朗読と演出の強みをデモで伝えるための改善
  - 動くと強いが、見せ方の文脈が必要
- **SHOW-PRELAUNCH**
  - 事前集客やクラファン前に必要な導線・説明・登録ページ
- **SHOW-BETA**
  - 小さく公開して触ってもらうための最低限の安定化
- **FOUNDATION**
  - 重要だが、外から見えにくい内部整理や将来のための整備

### 5-2. 今の優先順位を「見せる前提」で並べ替えた結果
#### 最優先
**SHOW-CORE: 外向きUI整備 / 試作の見える化**
- トップページの見た目と導線整理
- 読書ページの見た目と没入感調整
- AIっぽくないUIトーンへの統一
- スマホで見た時の第一印象改善
- サンプル導線の整理

#### 2位
**SHOW-DEMO: 朗読と演出の見せ場強化**
- 朗読再生の見栄え最終調整
- 追従・自動スクロール・BGM切替の見せ場強化
- 動的演出の中で、デモで刺さるものの優先整備
- サンプル作品1〜3本で完成した体験を作る

#### 3位
**SHOW-PRELAUNCH: 事前集客で必要なページ**
- サービス説明ページ
- 特徴紹介ページ
- 先行登録 / 通知登録ページ
- お知らせ / 開発進捗ページ
- FAQ
- お問い合わせ
- 利用規約
- プライバシーポリシー

#### 4位
**SHOW-BETA: 小さくβ公開するための安定化**
- 読む
- 朗読を再生する
- 演出が見える
- 作品一覧に入る
- ページ遷移が自然
- スマホでも最低限崩れない
- エラーや空状態が露骨に崩れない

#### 5位
**SHOW-DEMO / FOUNDATION: 動的演出の精度改善**
- scene_break と timestamp 精度改善
- cue ごとの詳細な BGM フェード制御
- 動的演出種類の追加
- autoplay と dynamic cue の相互作用確認

#### 6位
**FOUNDATION: episodes / recordings / policy の repo 正史整備**
- migration の棚卸し
- policy の棚卸し
- repo / DB 差分の整理
- 今後の追加作業で事故らないようにする

#### 7位
**FOUNDATION: 他小説投稿サイト参考機能の追加整理**
- なろう / ハーメルン等を参考にした導線整理
- 追加した方がいい最小機能の整理
- 何を参考にし、何を差別化するかの線引き

#### 8位
**SHOW-CORE / BRAND: ロゴ / アイコン導入**
- ヘッダー反映
- ブランド統一
- 画像仕様が揃い次第着手

## 7. 子チャット運用の正式テンプレ
- 子チャットの役割は **VS Code local ファイル変更指示を出すこと**
- 実際に反映・実行するのはユーザー側
- GitHub 上に存在しても、VS Code local に無いファイルを前提に実装を進めない
- repo にあること、local にあること、push 済みであることを分けて確認する
- repo と VS Code local にズレがあったら、その場で再判定を出す
- 正式な報告先は親チャットのみ
- 子チャットから別の子チャットへの正式引き継ぎ文は作らない
- チャットが重くなった場合も、子チャットは親チャット向け報告のみを出す
- 次の子チャットへ渡す正式な引き継ぎ文は親チャットが作る
- 必ず repo 実体を確認して、前後の形に厳密に合わせる
- 差し込み位置が曖昧なら、部分差し込みではなく丸ごと置換用の完成コードを優先する
- 同期判定は途中表示ではなく **最終実測値** を優先する

## 9. 同期と docs 運用
- GitHub にあるだけで local に無い状態は、正史確認には使えても実作業継続前提にはしない
- 次の作業前に必ず local を同期する
- 用語を分ける
  - repo正史反映済み
  - local反映済み
  - 両方反映済み
- 「反映済み」は原則、GitHub と local の両方が揃った時だけ使う
- docs cleanup は毎回必須ではない
- 重複 docs が新たに増えた時だけ cleanup 対象にする
